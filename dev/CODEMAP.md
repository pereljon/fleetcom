# CODEMAP - where things live

Owns: a one-line purpose for each function or module, for locating code. Does NOT hold logic flow (dev/SKELETON.md) or architecture (dev/IMPLEMENTATION-SPEC.md).
Maintain: add a row when code lands; keep each purpose to one line.

| function/module | one-line purpose |
|-----------------|------------------|
| `src/fleetcom/db.py` | schema DDL for tasks/events/contacts; `connect(path, *, create=False)` (expands `~`, refuses a missing file, and an existing file with no `schema_version`, unless `create`; opens with `mode=rw`), `_enable_wal` (bounded retry of the WAL switch), `_stored_version` (reads `schema_version`, or `None` on a new file), `migrate` (skips its write when the version is current), `normalize_stored_times` (startup repair that rewrites stored times in UTC and returns `(rows fixed, list of (table, id) left)`; `_TIME_COLUMNS` lists the columns it checks, `_UTC_GLOB` the format it leaves alone), `default_db_path` |
| `src/fleetcom/util.py` | `new_id` (uuid4), `now_iso` (UTC RFC3339-ish timestamp), `capped` (fetches `limit + 1` rows to report truncation and validates `limit`), `to_utc` (rewrites one ISO-8601 time as UTC in `now_iso` format; reads no offset as UTC, `""` as null, and raises `ValueError` on an unparseable value), `normalize_times` (applies `to_utc` to the named fields of a dict and names the field in an error) |
| `src/fleetcom/crud.py` | generic, injection-safe CRUD engine (`create`/`get`/`update`/`delete`) shared by all entities; `update` and `delete` raise `NotFoundError` (a `ValueError`) when no row has the id; field names are validated against a fixed allow-list before being interpolated into SQL identifier positions |
| `src/fleetcom/tasks.py` | task CRUD (absorbs former reminders via `remind_at`; `TIME_FIELDS` names `due` and `remind_at`, which writes normalize to UTC); `list(due_now=True)` bespoke query; `accept`/`reject` bespoke status-gated transitions |
| `src/fleetcom/events.py` | event CRUD (`TIME_FIELDS` names `start` and `end`, which writes normalize to UTC) + `list_in_range` (start between two ISO timestamps; normalizes both bounds and refuses an empty one) |
| `src/fleetcom/contacts.py` | contact CRUD + `search` (substring match on name/tags, with LIKE-wildcard escaping) |
| `src/fleetcom/agenda.py` | `today(conn)`: cross-entity aggregator combining `tasks.list(due_now=True)` and `events.list_in_range` for the current day |
| `src/fleetcom/server.py` | `build_server(conn)` registers all 15 MCP tools as closures over one connection; `_anticipated` decorator converts anticipated storage errors (bad enum, CHECK violation, unknown field) into `ToolError` so callers see the real reason, and maps `database is locked` to a `ToolError` with a retry hint; `_parse_args` parses `--db`/`FLEETCOM_DB_PATH` precedence, `--create-db`, and `--version` (prints `fleetcom-mcp <version>` and exits 0); `main()` is the `fleetcom-mcp` entry point, runs the startup time repair and reports it on stderr, and exits with status 1 when the database cannot be opened |
| `src/skills/fleetcom/SKILL.md` | fleet-facing skill doc: fleetcom vs. memory/chat routing rule, task conventions (handles, owner="user" meaning, accept/reject), wiring notes |
| `src/skills/fleetcom/references/tools.md` | one-line usage example per registered MCP tool, grepped from `server.py` rather than hand-counted |
| `scripts/promote.sh` | Refuses unknown arguments, a dirty tree, a branch other than `main`, a stale `uv.lock`, and failing tests or linters; then (full promote) installs `fleetcom-mcp` with `uv.lock` constraints and checks its `--version`, swaps the skill into `deploy/`, and stamps the promoted SHA |
